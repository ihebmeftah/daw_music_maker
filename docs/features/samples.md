# Samples — audio uploads, browser, sampler and chopping

## 1. Purpose and user stories

- I **upload audio files** (WAV, MP3, OGG, FLAC, **max 10 MB**) by **dropping them anywhere
  on the studio** or with the browser's upload button; each file shows a **progress bar**
  (errors stay listed until dismissed).
- The **browser** (left of the workspace) lists the built-in drums and the project's
  uploads. I **drag** a sound onto the **channel rack** (new channel, ready for steps /
  piano roll) or an upload onto the **playlist** (an audio clip starting at that bar, its
  length computed from the sample's duration at the current tempo). Tap previews,
  double-tap adds a channel and opens its sampler.
- **Sampler** (double-click a channel, or "Open sampler" in its menu): waveform with
  **start / end trim handles**, **volume**, **pan** and **pitch** (±24 semitones, added to
  each note's pitch), preview, and **chop** — split the trimmed region into 2 / 4 / 8 / 16
  equal slices, each added as a new channel ("Name 1…N").
- Deleting an upload removes the channels and playlist clips that use it.
- Read members and visitors can preview and play; only owners and write members upload,
  edit the sampler, chop or delete.

## 2. Screens / routes and endpoints

- Studio (`/projects/:id/studio`): `SampleBrowser`, `_AudioDropZone` (`desktop_drop`
  DropTarget over the whole studio), `SamplerDialog`, drag targets in `ChannelRack` and
  `PlaylistView`. Upload button uses `file_picker`.
- Server `client.sample` (`SampleEndpoint`):
  - `requestUpload(RequestSampleUploadRequest)` → `SampleUploadTicket { uploadId,
    uploadDescription }` (Serverpod upload description limited to the declared size and
    10 MB, `preventOverwrite`, for the **server-generated** private path
    `projects/<projectId>/samples/<uploadId>.<ext>`).
  - client: `FileUploader(uploadDescription).upload(stream, length)` — the bytes are
    streamed in 64 KB chunks and counted for the progress bar.
  - `finishUpload(FinishSampleUploadRequest)` → verifies the upload, re-checks size and
    **magic bytes** against the extension (invalid files are deleted), reads WAV headers for
    the duration and a **200-point waveform** (stored with the sample, so clients don't
    decode audio), and creates the `Sample`. Idempotent per upload id.
  - `list(projectId)` → samples with **12-hour temporary download URLs** (private storage).
  - `delete(sampleId)` → removes the row (channels / clips cascade) and the file.
- `client.channel`: `create` accepts `sampleId` (uploaded) or `sample` (built-in);
  `update` carries `pan`, `pitch`, `startFrac`, `endFrac`; `chop(channelId,
  ChopChannelRequest)` creates the slice channels.
- `client.playlist`: clips can be audio clips (`sampleId` + `lengthBars`).
- Flutter audio: `SoundSource` (`BuiltinSound` / `UploadedSound`) and
  `AudioEngine.play(source, volume, rate, pan, startFrac, endFrac)` — 4 voices per source,
  `setBalance` for pan, seek + timed stop for the region. Built-in waveforms come from the
  bundled WAVs (`builtinPeaksProvider`, `wav_peaks.dart`).

## 3. Models

- Enum `AudioFormat { wav, mp3, ogg, flac }`.
- Entity `Sample` (`sample`): `projectId` (cascade), `name`, `format`, `sizeBytes`,
  `durationMs?`, `peaks?`, `storagePath` (unique), `uploadedById`.
- `Channel`: `sample?`, `sampleId?` (cascade), `pan`, `pitch`, `startFrac`, `endFrac`.
- `PlaylistClip`: `patternId?`, `sampleId?` (cascade), `lengthBars?`.
- DTOs `RequestSampleUploadRequest`, `FinishSampleUploadRequest`, `ChopChannelRequest`;
  responses `SampleUploadTicket`, `SampleResponse`.
- Migration `20261111192010776` (non-destructive: new table, new columns with defaults, two columns
  made nullable).

## 4. Validation rules and security notes

| Rule                    | Value                                                        |
| ----------------------- | ------------------------------------------------------------ |
| File size               | 1 B – 10 MB (upload description + re-checked after upload) |
| Formats                 | WAV, MP3, OGG, FLAC — extension **and** magic bytes          |
| Samples per project     | ≤ 64                                                         |
| Pan / pitch             | −1 … 1 / ±24 semitones                                       |
| Region                  | 0 ≤ start < end ≤ 1 (≥ 0.001 wide)                           |
| Chop slices             | 2, 4, 8 or 16 (channel cap 32 applies)                       |
| Audio clip length       | 1–64 bars; clips can't overlap on a track                    |

- Paths are generated by the server from the project id and a random upload id; clients
  never send paths. Files live in **private** storage; download URLs are temporary and
  only handed to users who can see the project.
- Channels and clips may only reference samples of their own project.
- Client checks (`Validators.audioFile`) are for UX; the server re-validates everything.

## 5. How it is tested

- Server: `audio_inspector_test` (format detection, display names, magic bytes, WAV parsing
  for 8/16/24/32-bit, float, stereo, extensible, odd chunks), channel rule / slice and
  playlist audio-clip rule tests, `sample_endpoint_test` (tickets, size / type / cap,
  finish with real database storage incl. mismatched bytes and idempotency, list URLs,
  delete cascades, auth / ownership) and `channel_sampler_test` (sampler settings, chop).
- Flutter: validators, `wav_peaks`, sound sources, repository upload / chop / sampler
  calls, ViewModel uploads (progress, errors), delete cascade, sampler settings, chop,
  playback with uploaded sources, audio clips, browser / sampler / drag-and-drop widget
  tests. Tests use `FakeAudioEngine`.
- Not covered by automated tests: real audio output and OS-level file drops (exercised
  through the `DropTarget` callback and `uploadFiles`).
