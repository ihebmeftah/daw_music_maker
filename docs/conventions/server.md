# Server conventions (`daw_music_maker_server`)

Applies to everything under `daw_music_maker_server/`. Read together with
[testing.md](testing.md), [security.md](security.md) and
[documentation.md](documentation.md). The Serverpod skills in `.agents/skills/serverpod-*`
are the reference for exact syntax.

## Feature-first layout with separated models

```
lib/
├── server.dart                    # bootstrap + auth (already configured — extend, don't replace)
└── src/
    ├── auth/                      # Serverpod auth endpoints (existing)
    ├── core/
    │   ├── exceptions/            # app_exception.spy.yaml, error_code.spy.yaml (enum)
    │   ├── security/              # auth_guard.dart (requireUserId), ownership checks
    │   ├── validation/            # validation_rules.dart, validator.dart
    │   └── pagination/            # page_request.spy.yaml, page_limits.dart
    └── features/
        └── <feature>/             # e.g. projects, patterns, tracks, samples, mixer
            ├── entities/          # <name>.spy.yaml        — DB tables, serverOnly: true
            ├── dtos/              # create_<name>_request.spy.yaml, update_<name>_request.spy.yaml
            ├── responses/         # <name>_response.spy.yaml — what the client receives
            ├── mappers/           # <name>_mapper.dart     — Entity → Response extensions
            ├── repositories/      # <name>_repository.dart — DB access only (ORM)
            ├── services/          # <name>_service.dart    — business logic, validation, ownership
            └── endpoints/         # <name>_endpoint.dart   — thin RPC layer
```

### The three model kinds — never mix them

| Kind         | Folder        | YAML                                 | Exposed to client? |
| ------------ | ------------- | ------------------------------------ | ------------------ |
| **Entity**   | `entities/`   | `class:` + `table:` + `serverOnly: true` | **No**         |
| **DTO**      | `dtos/`       | `class:` (no table), suffix `Request`    | Yes (input)    |
| **Response** | `responses/`  | `class:` (no table), suffix `Response`   | Yes (output)   |

- Endpoints **accept DTOs** and **return Responses** (or `List<…Response>` / a page
  response). They never accept or return an entity — `serverOnly: true` enforces this.
- DTOs never contain `id` for creation, `ownerId`, `createdAt`, or other server-owned fields.
- Entity → Response mapping lives in `mappers/` as extension methods
  (`extension ProjectMapper on Project { ProjectResponse toResponse() }`). DTO → Entity
  construction happens in the service.
- **No hand-written serialization**: never write `toJson`/`fromJson`/`toMap`/"normalize"
  methods — Serverpod generates serialization for every `.spy.yaml` class.

### Entity template (UUID ids)

```yaml
### A music project owned by a user.
class: Project
serverOnly: true
table: project
fields:
  ### Primary key, generated by the database (UUID v7).
  id: UuidValue?, defaultPersist=random_v7
  ### The auth user that owns the project.
  ownerId: UuidValue
  ### Display name, 1–80 chars.
  name: String
  ### Tempo in beats per minute.
  bpm: double, default=140.0
  createdAt: DateTime, default=now
  updatedAt: DateTime, default=now
indexes:
  project_owner_idx:
    fields: ownerId
```

- **Every table uses `id: UuidValue?, defaultPersist=random_v7`.** No serial `int` ids.
- Foreign keys are `UuidValue`; every foreign key and every column used in a `where` gets an index.
- Add `createdAt` / `updatedAt` to every table.

### Layer rules

- **Endpoint**: `requireLogin => true` (default for every feature endpoint), get the user id via
  the auth guard, call one service method, return a Response. No ORM calls, no business logic.
- **Service**: validation, ownership/authorization checks, orchestration, transactions
  (`session.db.transaction`). Receives `Session` + DTOs, returns Responses (via mappers).
  Pure helpers (validation, math) are plain functions/classes so they are unit testable
  without a database.
- **Repository**: only ORM calls (`Project.db.find…`, `insertRow`, …). Every query that reads
  user data filters by `ownerId` (or checks membership). Always paginate lists
  (`limit` ≤ `PageLimits.max`).

### Errors

- Throw only serializable exceptions defined in `core/exceptions/` (e.g. `AppException` with
  an `ErrorCode` enum: `notFound`, `forbidden`, `validation`, `conflict`) plus optional
  `fieldErrors: Map<String, String>?`.
- Never let raw exceptions/stack traces reach the client. Log them with `session.log(...,
  level: LogLevel.error, exception: e, stackTrace: st)`.
- Return `notFound` (not `forbidden`) when a user requests a resource they don't own, so ids
  can't be probed.

### Migrations

- After changing any `table` model: `create_migration` then `apply_migrations` (serverpod MCP).
- Only hand-edit `migration.sql` to preserve data (see AGENTS.md); the final schema must
  equal `definition.sql`.

### Naming

- Endpoint classes: `<Feature>Endpoint` → client accessor `client.<feature>`.
- Methods: verbs — `create`, `getById`, `list`, `update`, `delete`.
- Files `snake_case`; model class names `PascalCase`; table names `snake_case` singular.
