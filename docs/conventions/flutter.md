# Flutter conventions (`daw_music_maker_flutter`)

Applies to everything under `daw_music_maker_flutter/`. Read together with
[testing.md](testing.md), [security.md](security.md) and
[documentation.md](documentation.md).

## Stack

| Concern            | Package(s)                                                        |
| ------------------ | ----------------------------------------------------------------- |
| Routing            | `go_router` + `go_router_builder` (typed routes)                  |
| State / ViewModels | `flutter_riverpod`, `riverpod_annotation` + `riverpod_generator`  |
| DI                 | `get_it` + `injectable` / `injectable_generator`                  |
| Immutable state    | `freezed` + `freezed_annotation`                                  |
| Assets             | `flutter_gen_runner` (type-safe `Assets.*`)                       |
| Codegen            | `build_runner`                                                    |
| Mocks (tests)      | `mocktail`                                                        |
| Backend            | `daw_music_maker_client` (generated by Serverpod — never edit)    |

Add missing packages with `flutter pub add` (or the `dart` MCP `pub` tool) when the
first feature needs them. Run codegen with:

```sh
dart run build_runner build --delete-conflicting-outputs   # one-off
dart run build_runner watch --delete-conflicting-outputs   # while developing
```

Generated files (`*.g.dart`, `*.freezed.dart`, `*.gr.dart`, `injection.config.dart`,
`lib/gen/**`) are never edited by hand.

## Architecture: MVVM, feature-first

```
lib/
├── main.dart                 # bootstrap: configureDependencies() → ProviderScope → DawApp
├── driver.dart               # flutter_driver entry point (used by the Serverpod runner)
├── app/
│   ├── app.dart              # DawApp: MaterialApp.router, theme, router
│   ├── di/
│   │   ├── injection.dart    # final getIt = GetIt.instance; @InjectableInit configureDependencies()
│   │   └── register_module.dart  # @module: Client, SessionManager, AudioEngine, …
│   └── router/
│       ├── app_router.dart   # GoRouter instance (exposed via a Riverpod provider)
│       ├── routes.dart       # @TypedGoRoute definitions (+ routes.g.dart)
│       └── route_guards.dart # auth redirect logic
├── core/
│   ├── theme/                # app_colors.dart, app_text_styles.dart, app_spacing.dart,
│   │                         # app_radii.dart, daw_colors.dart (ThemeExtension), app_theme.dart
│   ├── validation/           # validators.dart, validation_rules.dart (mirror the server)
│   ├── errors/               # failure.dart, error_mapper.dart (Serverpod exceptions → Failure)
│   ├── audio/                # AudioEngine interface + implementation (mockable)
│   ├── extensions/           # BuildContext / num / Duration extensions
│   └── constants/            # durations, limits, PPQ, etc.
├── gen/                      # flutter_gen output (assets.gen.dart, fonts.gen.dart)
├── shared/
│   └── widgets/              # reusable components (see "Shared components")
└── features/
    └── <feature>/            # e.g. auth, projects, channel_rack, piano_roll, playlist, mixer, browser
        ├── data/
        │   ├── <feature>_repository.dart        # abstract interface
        │   └── <feature>_repository_impl.dart   # @LazySingleton(as: …) — calls client.<endpoint>
        └── presentation/
            ├── views/<name>_view.dart           # screens (View)
            ├── view_models/<name>_view_model.dart  # @riverpod Notifier/AsyncNotifier (ViewModel)
            ├── state/<name>_state.dart          # @freezed UI state
            └── widgets/                         # widgets private to this feature
```

### Layer rules

- **View** (`ConsumerWidget` / `ConsumerStatefulWidget`): renders state and forwards user
  intents to the ViewModel. No business logic, no direct repository/client calls, no
  `getIt` calls.
- **ViewModel** (`@riverpod class XViewModel extends _$XViewModel`): holds UI state
  (`@freezed` state or `AsyncValue<T>`), validates input, calls repositories, maps errors to
  `Failure`. Never imports `package:flutter/material.dart` (no `BuildContext`, no widgets).
- **Repository**: the only place that talks to `client.*` endpoints. Returns domain/response
  models from `daw_music_maker_client` and throws `Failure` (mapped from Serverpod exceptions).
- Dependencies point **View → ViewModel → Repository → Client**. Never backwards; features
  do not import each other's `data/` or `presentation/` internals — shared things move to
  `core/` or `shared/`.

### DI: get_it + Riverpod bridge

- Infrastructure (Serverpod `Client`, repositories, `AudioEngine`, storage) is registered in
  get_it with `injectable` annotations (`@lazySingleton`, `@LazySingleton(as: Interface)`,
  `@module`).
- ViewModels get dependencies through a Riverpod provider that reads get_it, so tests can
  override them with `ProviderScope(overrides: [...])`:

  ```dart
  /// Exposes the [ProjectRepository] registered in get_it to Riverpod.
  @riverpod
  ProjectRepository projectRepository(Ref ref) => getIt<ProjectRepository>();
  ```

- Never call `getIt<…>()` inside widgets or ViewModels directly.

### Routing (go_router)

- All routes are typed (`@TypedGoRoute`) in `app/router/routes.dart`; navigate with
  `const ProjectRoute(id: …).go(context)` — no string paths in widgets.
- Route params that identify entities are **UUID strings**; parse with `UuidValue.fromString`
  inside the route, and show a not-found view on invalid input.
- Auth redirect lives in `route_guards.dart` and listens to `client.auth.authInfoListenable`
  (via `refreshListenable`).

## Theme, colors, text styles, assets

- **No hard-coded colors, text styles, spacing or radii in widgets.** No `Colors.x`,
  `Color(0x…)`, `TextStyle(...)`, `EdgeInsets.all(13)` literals outside `core/theme/`.
- `AppColors` = raw palette (private to `core/theme`). Widgets use semantic tokens:
  - `Theme.of(context).colorScheme` for Material roles.
  - `context.dawColors` (a `ThemeExtension<DawColors>`) for DAW-specific roles: track colors,
    meter green/amber/red, playhead, grid lines (bar/beat/step), selection, mute/solo.
  - `context.textStyles` (`AppTextStyles`) — includes a monospaced style for BPM,
    time display and numeric readouts.
  - `AppSpacing.xs/sm/md/lg/xl`, `AppRadii.*` for layout constants.
- The app is dark-first (DAW style) but both `AppTheme.dark` and `AppTheme.light` must exist.
- Assets live in `assets/` grouped by type and are accessed only through flutter_gen:

  ```
  assets/
  ├── images/        # png/jpg/webp (+ 2.0x/3.0x variants)
  ├── icons/         # svg icons
  ├── fonts/
  ├── audio/samples/ # bundled default kits (kick, snare, hat, …)
  └── config.json    # Serverpod app config — keep
  ```

  Use `Assets.icons.play.svg()` / `Assets.audio.samples.kick` — never raw `'assets/...'` strings.

## Shared components (`lib/shared/widgets/`)

Before building UI, check `shared/widgets/` and reuse. Grouped by purpose:

- `buttons/` — `DawButton`, `DawIconButton`, `DawToggleButton` (mute/solo/record)
- `inputs/` — `DawTextField` (wraps `TextFormField` + validator), `DawDropdown`, `DawSlider`
- `daw/` — `Knob`, `Fader`, `LevelMeter`, `StepButton`, `BpmField`, `TimeDisplay`, `TransportBar`
- `feedback/` — `LoadingIndicator`, `ErrorView` (takes a `Failure` + retry), `EmptyState`, snackbars
- `layout/` — `Panel`, `ResizableSplit`, `ResponsiveScaffold`

Rules:
- A widget used by 2+ features moves to `shared/widgets/`. Each shared widget has a widget
  test and dartdoc with a usage example.
- **Extract widgets into classes, not helper methods.** No `Widget _buildHeader()` methods —
  create a `const`-constructible `_Header` / `Header` widget instead (better rebuilds, testable).
- Prefer `const` constructors; keep `build` methods short (≈ < 60 lines).

## No hand-written serialization

- Never hand-write `toJson` / `fromJson` / `toMap` / "normalize" methods. Network models come
  from `daw_music_maker_client` (Serverpod generates serialization). Local models that need
  JSON use `freezed` + `json_serializable`.
- Converting between types uses typed mapper extensions (`extension on ProjectResponse {
  ProjectCardData toCardData() }`), never `Map<String, dynamic>`.

## Forms & validation

- Every user input lives inside a `Form` with a `GlobalKey<FormState>`; fields use
  `DawTextField` with validators from `core/validation/validators.dart`.
- `ValidationRules` (lengths, BPM range, etc.) **mirrors the server constants** in
  `daw_music_maker_server/lib/src/core/validation/validation_rules.dart`. Change both together
  and keep their tests in sync.
- Validators are pure functions returning `String?` and are unit tested.
- Client-side validation is for UX only; the server always re-validates (see security.md).
- Disable submit buttons while a request is in flight; show server errors via `ErrorView` /
  field errors, never raw exception text.

## IDs

- All entity ids are `UuidValue` (from the generated client). Never use `int` ids or
  list indexes as identity. Generate client-side ids (e.g. for optimistic notes/steps) with
  `const Uuid().v7obj()` from `package:uuid`.

## DAW-specific guidance

- Timeline math uses integer **ticks** (`kPpq = 960` per quarter note); convert to
  seconds/pixels only at the edges. Never store positions as `double` seconds.
- Audio playback/scheduling sits behind the `AudioEngine` interface in `core/audio/` so
  ViewModels stay testable; inject a fake in tests.
- Piano roll, playlist, step grid and meters use `CustomPainter` + `RepaintBoundary`; the
  playhead animates via a `Listenable`/`Ticker`, not by rebuilding providers at 60 fps.
- Use `ref.watch(provider.select(...))` to limit rebuilds in dense editors.
- Desktop-first layout with keyboard shortcuts (`Shortcuts`/`Actions`), but stay usable on
  tablets via `LayoutBuilder`.

## Naming

- Files: `snake_case.dart`; one public class per file, file named after it.
- Suffixes: `…View`, `…ViewModel`, `…State`, `…Repository`, `…RepositoryImpl`, `…Route`.
- Providers generated by riverpod_generator keep default names (`projectListViewModelProvider`).
